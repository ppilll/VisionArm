产品目标选择无刷电机云台，原因是其更适合摄像头连续跟随、低抖动和稳定成像。

但第一版不做无刷电机底层驱动和 FOC 控制。第一版优先选择带独立控制板的成品无刷云台，由 STM32F1 或 RK3588 通过 UART/CAN 下发目标角度、角速度或跟随命令。

如果无刷云台协议、供电、参数整定或闭环控制阻塞，则降级为二自由度舵机云台完成最小闭环。

验收优先级：

- P0：云台能根据 dx/dy 安全调整摄像头方向
- P1：无刷云台能接收目标角度或速度命令并连续跟随
- P2：无刷云台低抖动、低延迟、平滑控制优化
- 禁止项：第一版不自研 BLDC FOC、不自研 IMU 姿态稳定算法

第一目标：OV5640，目标分辨率 1280x720，目标帧率 60fps。

但 OV5640 不直接等于第一版成功条件。第一版摄像头验收以 RK3588 Linux 侧 V4L2 实测为准，必须能够枚举 /dev/videoX、查询格式、使用 mmap buffer 稳定采集，并记录实际 fps。

摄像头 fallback：

- P0：任意稳定 V4L2 摄像头完成最小闭环，允许 USB UVC 摄像头
- P1：OV5640 完成 V4L2 采集，720p@30fps 或 VGA/720p 可稳定运行
- P2：OV5640 达到 720p@60fps，并记录 fps、buffer、丢帧和延迟证据

当前硬件目标为 RK3588 + OV5640 + STM32F1 + 无刷电机云台。

该组合符合产品方向，但第一版风险高于 USB UVC + 舵机云台方案。因此第一版采用“双路线边界”：

- 产品目标路线：OV5640 + 无刷电机云台
- 最小闭环保底路线：USB UVC 摄像头 + 二自由度舵机云台

项目主目标不是证明 OV5640 或无刷云台本身，而是完成边缘视觉云台追踪系统闭环。

若 OV5640 在 V2 阶段阻塞超过预期，则允许切换到 USB UVC 摄像头继续 V3~V7，不允许因为摄像头 bring-up 阻塞整个项目。

若无刷云台在 V6 阶段阻塞超过预期，则允许切换到舵机云台继续 V7，不允许因为无刷控制复杂度阻塞最小闭环。

第一版必须保留：

- 采集
- 识别
- dx/dy 偏差计算
- Linux → MCU 控制链路
- 云台执行
- 状态/视频回传
- 测试报告

第一版不得变成：

- OV5640 bring-up 项目
- 无刷 FOC 控制项目
- CAN 总线调试项目
- 足球识别 AI demo
