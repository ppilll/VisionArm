# 电气检查
Physical layer:
    RS-485, 2-wire, half-duplex

RK3588:
    UART3
    candidate tty = /dev/ttyS3
    board-level automatic direction control
    application does not operate DE/RE GPIO
    application does not call TIOCSRS485 by default

MCU:
    STM32F103ZET6
    USART2
    PD7 controls RS-485 direction
    PD7 = 0 receive
    PD7 = 1 transmit

Bus ownership:
    Linux is the only bus master
    MCU unsolicited transmission is forbidden

# token 规则
CONTROL_UPDATE
    Linux → MCU
    MCU 不响应
    Linux 可连续发送
    latest-value semantics

HELLO
    Linux → MCU
    Linux 暂停普通 CONTROL_UPDATE
    MCU → HELLO_ACK
    MCU 完成发送后释放总线
    Linux 收到响应或超时后重新取得总线

HEARTBEAT
    Linux → MCU
    该消息同时授予 MCU 一次 STATUS 发送权
    Linux 暂停普通 CONTROL_UPDATE
    MCU → STATUS
    响应结束或超时后 Linux 恢复发送

PING
    Linux → MCU
    MCU → PONG

REMOTE_STOP_REQUEST
CLEAR_REMOTE_STOP
    Linux → MCU
    MCU → ACK/NACK

MCU 不允许：
    独立定时发送 STATUS
    独立发送 HEARTBEAT
    无请求发送诊断消息

## Linux 总线状态
IDLE  空闲
TX_STREAMING  发送流
TX_REQUEST  发送请求
WAIT_TURNAROUND  等待响应
WAIT_RESPONSE  等待超时
RECOVER_AFTER_TIMEOUT  超时后恢复
STOPPING  停止

IDLE
  → TX_STREAMING
      CONTROL_UPDATE 完成后直接回 IDLE

IDLE
  → TX_REQUEST
      HELLO/HEARTBEAT/PING/reliable command

TX_REQUEST
  → WAIT_TURNAROUND
  → WAIT_RESPONSE

WAIT_RESPONSE
  → IDLE               收到合法预期响应
  → RECOVER_AFTER_TIMEOUT
  → IDLE               响应超时，重新取得总线

禁止发送 CONTROL_UPDATE
允许记录/覆盖 latest-control mailbox
不得把旧 control 排成历史 FIFO
收到响应或超时后，只发送最新 control
