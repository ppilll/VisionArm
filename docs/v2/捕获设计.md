V2 V4L2 捕捉设计
1.设计目标
构建一个确定性的 V4L2 mmap 捕获模块，无需依赖 OpenCV、GStreamer、FFmpeg、RKNN 或显示服务器即可输出帧数据和元数据。
2.输入配置
- 设备路径：运行时参数  
- 宽度：运行时参数  
- 高度：运行时参数  
- FourCC：运行时参数  
- 帧率：运行时参数  
- 缓冲区数量：运行时参数  
- 帧数：运行时参数  
- 超时时间：运行时参数
不依赖硬件的值被编译为默认值。
3.初始化流程
1. 打开2. VIDIOC_QUERYCAP3. 选择单平面或多平面API4. VIDIOC_G_FMT5. VIDIOC_S_FMT6. VIDIOC_G_FMT 确认7. 可选 `VIDIOC_S_PARM`8. VIDIOC_G_PARM 确认9. VIDIOC_REQBUFS10. VIDIOC_QUERYBUF11. mmap12. 初始 `VIDIOC_QBUF`13. VIDIOC_STREAMON
4.为什么使用 mmap
- 使用 V4L2 流式 I/O 模型。  
- 通过交换缓冲区引用，而非通过 `read` 复制每一帧。  
- 提供来自 `VIDIOC_DQBUF` 的序列号、时间戳、标志位和 `bytesused`。  
- 建立通往后续 DMABUF/RGA 工作的迁移路径。
5.为什么 OpenCV VideoCapture 不是主要的实现方式
OpenCV 隐藏了节点能力选择、协商的 FourCC、缓冲区 API、序列、时间戳标志以及底层队列行为。仅可用于离线验证。
6.单平面和多平面处理
- 从 `device_caps` 中确定支持情况。
- 只有在所选节点支持时，才优先使用单平面模式。
- 如果仅包含 `VIDEO_CAPTURE_MPLANE`，则使用 `v4l2_pix_format_mplane` 和一个 `v4l2_plane` 数组。
- 映射 `VIDIOC_QUERYBUF` 返回的每个平面。
- 切勿通过单平面结构传递 `_MPLANE` 节点。
7. 格式选择
所选格式必须来自 `--list-formats-ext`。
评估维度：
- 驱动原生支持  
- 压缩或原始格式  
- CPU 转换/解码成本  
- 内存带宽  
- RKNN 预处理兼容性  
- 步长和平面布局  
- 可用分辨率和帧间隔  
- 测量的稳定性
8. 缓冲策略
- 初始请求缓冲区数量：可配置  
- 最小接受数量：2  
- 在开启流前将所有已分配的缓冲区加入队列  
- 每个缓冲区在提取元数据并可选保存样本后立即重新入队  
- 稳定性测试期间不保存每一帧
9. 问卷策略
- DQBUF 之前调用 `poll()`  
- 可配置超时时间  
- 计数超时  
- 重复连续超时后终止操作  
- 将 `EAGAIN` 视为可重试的错误  
- 记录 `EIO` 和缓冲区错误标志
10. 框架元数据
struct FrameBuffer {
const void* data;
std::size_t bytes_used;
uint32_t width;
uint32_t height;
uint32_t pixel_format;
uint64_t frame_id;
uint32_t v4l2_sequence;
int64_t capture_timestamp_ns;
int64_t dequeue_monotonic_ns;
uint32_t timestamp_flags;
}};

11. 时间戳设计
记录：
- V4L2 timeval  
- 时间戳类型掩码  
- 时间戳源掩码  
- DQBUF 完成 CLOCK_MONOTONIC  
- 时间戳回归  
- 帧间时间戳差值  
- 差值抖动
不要将DQBUF时间戳称为“曝光时间”。
12. 序列间隔设计
对于连续序列的值：
```
delta = unsigned(current - previous)  
gap = delta > 1 ? delta - 1 : 0
```

记录间隙事件数量和估计的缺失帧数量。

13. 帧保存  
- 仅保存前N帧。  
- MJPG/JPEG：将编码后的帧边界保存为一个.jpg文件。  
- 压缩/原始YUV：保存实际使用的字节。  
- 多平面原始数据：按文档中指定的平面顺序连接各平面，并保留平面/行距元数据。  
- 在日志中记录平面/行距元数据。  
- 通过文件大小、头部信息、哈希值及离线解码器进行验证。
14. 错误处理  
- 每次 ioctl 失败都会记录 errno。  
- 所有致命路径在适用情况下会调用 STREAMOFF。  
- 所有映射均被取消映射。  
- 文件描述符已关闭。  
- SIGINT/SIGTERM 请求控制退出。
15. 下游接口
- V3 消耗有效载荷、FourCC、宽度、高度、行距和字节数。
- V8 消耗捕获时间戳、时间戳标志、解队时间戳和序列号。
- V2 不执行推理或音视频同步。

V4L2 通过缓冲区类型区分单平面和多平面 API。多平面操作需要使用 `v4l2_pix_format_mplane` 和 `v4l2_plane` 数组来处理 `QUERYBUF/QBUF/DQBUF`；每个平面可能都需要单独的 `mmap()`。:contentReference[oaicite:8]{index=8}:contentReference[oaicite:9]{index=9} 5.3 `performance_report.md`
