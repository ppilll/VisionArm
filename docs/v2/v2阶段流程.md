## Build V2 capture application

```bash
cmake -S src/linux_app/camera \
      -B build/v2_camera \
      -DCMAKE_BUILD_TYPE=Release

cmake --build build/v2_camera -j"$(nproc)"
```

Run

```
./build/v2_camera/v4l2_capture \
  --device <VIDEO_DEVICE> \
  --width <WIDTH> \
  --height <HEIGHT> \
  --format <FOURCC> \
  --fps <FPS> \
  --buffers 4 \
  --frames 300 \
  --timeout-ms 2000 \
  --output-dir reports/images/v2 \
  --save-first 1 \
  --csv logs/v2_camera/frames.csv \
  --nonblock
  ```

## 设备识别流程
```text
Camera Connection
→ Kernel Driver Binding
→ Sensor/Subdevice/Media Entities
→ /dev/videoX Nodes
→ v4l2-ctl --list-devices
→ VIDIOC_QUERYCAP
→ driver/card/bus_info
→ capabilities/device_caps 判断
→ media topology 交叉验证
→ 选择真正的 capture node
```

## V4L2 mmap 流程

```
open()
→ VIDIOC_QUERYCAP
→ 检查 VIDEO_CAPTURE 或 VIDEO_CAPTURE_MPLANE
→ 检查 STREAMING
→ VIDIOC_G_FMT
→ VIDIOC_S_FMT
→ VIDIOC_G_FMT 再确认
→ 可选 VIDIOC_S_PARM
→ VIDIOC_G_PARM 再确认
→ VIDIOC_REQBUFS
→ VIDIOC_QUERYBUF
→ mmap()
→ VIDIOC_QBUF 全部 buffer
→ VIDIOC_STREAMON
→ poll()
→ VIDIOC_DQBUF
→ 读取 sequence/timestamp/flags/bytesused
→ 记录 DQBUF CLOCK_MONOTONIC
→ 处理或保存少量 frame
→ VIDIOC_QBUF
→ 循环
→ VIDIOC_STREAMOFF
→ munmap()
→ close()
```
驱动可以调整 S_FMT 请求，因此必须在 VIDIOC_S_FMT 后再次执行 VIDIOC_G_FMT，以驱动实际接受的 width、height、FourCC、stride、sizeimage 和 plane 数为准。 6.3 V2 到后续阶段的数据接口

```
V4L2 Capture
→ FrameBuffer {
    data / planes
    bytes_used
    width
    height
    bytes_per_line
    pixel_format
    frame_id
    v4l2_sequence
    capture_timestamp
    dequeue_monotonic_timestamp
    timestamp_flags
  }
→ V3 Preprocess / RKNN
→ V8 Video Timestamp Alignment
```


V2 保存 sequence 和 timestamp，是为了后续：

- 检测源端或应用端掉帧。
- 建立视频帧时间轴。
- 与 ALSA 时钟建立转换关系。
- 测量采集到处理链路的延迟。
- 分析抖动。

但 V2 不做真正的音视频同步。

V4L2 buffer flags 可以区分 timestamp 类型和来源，例如 TIMESTAMP_MONOTONIC、TSTAMP_SRC_EOF 和 TSTAMP_SRC_SOE；必须使用对应 mask 解析，不能把所有 timestamp 都默认解释成 monotonic 或曝光开始时间
